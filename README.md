1. 阅读 [课程要求](docs/course-rules.md) 和 [合作与格式规范](CONTRIBUTING.md)。课程原文以课程组发放的 PDF 为准。
2. 按 [加入仓库指南](docs/github-setup.md) 报名并接受协作邀请。
3. 在下表登记成员。用 Issue 认领任务，写清负责人、交付文件、验收方法和截止时间。
4. 从 `main` 创建任务分支，完成后发 Pull Request（PR，合并请求）；由另一位组员检查后合并。
5. 在 [过程记录](docs/records.md) 记录贡献、AI 使用核查和提交版本。

## 文件放在哪里

下表是按需创建的路径约定；没有材料时不用建空目录。

| 路径 | 内容 |
| --- | --- |
| `docs/` | 课程规则、合作指南、贡献与提交记录 |
| `proposal/` | 本组出题资料；公开说明与仅供审核的补充说明分开保存 |
| `problems/PXX/README.md` | 每题的问题、结果状态、材料索引和核查入口 |
| `problems/PXX/notes/` | 推导、证明、失败尝试和检查记录 |
| `problems/PXX/code/` | 实验或算法代码 |
| `problems/PXX/data/` | 可共享的必要输入数据及来源说明 |
| `problems/PXX/results/` | 小型结果表、参数和复现记录 |
| `paper/` | 出题说明、解题报告和最终报告的可编辑正文、参考文献及构建输出 |

正式题号公布后使用 `P01`、`P02` 等编号，`PXX` 只是占位符。出题 PDF 源文件放在 `paper/proposal/`，每题报告源文件放在 `paper/solutions/PXX/`，最终报告放在 `paper/final/`；相应构建产物放在各自 `_build/` 中。

## 每次交付的标准

- **理论题：** 命题、假设、证明或阶段性推导完整，标明关键引理位置和核查路径。
- **实验题：** 从依赖安装到得到结果都有可执行说明，写明输入、参数、随机种子、预期输出和验证方法。
- **共同要求：** 结论与证据对应，引用可追溯，贡献和 AI 核查记录已更新，由另一位组员检查。
- **正式提交：** 固定完整 commit SHA 和附件版本，由提交负责人发邮件并登记；PR 合并、GitHub 上传和邮件发出都不等于课程组已认定有效解答。

课程允许部分成果提交。每题明确标记“探索中”“部分完成”或“达到基本完成标准，待课程组核验”，收到课程组确认后再更新认可状态。
